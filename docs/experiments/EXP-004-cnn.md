# EXP-004. CNN Colab 학습과 합성 변형 평가

- 날짜: 2026-11-22
- 코드: `src/signlight/cnn.py`, `scripts/colab_cnn.sh`(이 문서와 같은 커밋)
- 환경: Colab T4(15GB), Python 3.13, TensorFlow 2.21. 로컬 패키지를 wheel로 설치(`--no-deps`)
- 데이터: Colab VM이 `kagglehub`로 받은 Kaggle 원본(Colab 캐시, 인증 불필요)을 로컬 디스크로 복사(72,000장, 33초). 분할은 로컬과 같은 `index.csv`(EXP-001)
- 모델: 합성곱 블록 4개(32-64-128-256, BN, ReLU, MaxPool) → GAP → Dropout 0.3 → Dense 24. 입력 128×128, 파라미터 약 39만 개
  - plain: 증강 없음
  - aug: 좌우 반전, 회전 ±5%, 이동 ±15%, 확대·축소 ±20%, 밝기 ±40%, 대비 ±30%
- 학습: Adam 1e-3, 배치 64, 최대 15 epoch, `EarlyStopping(val_accuracy, patience 3, restore_best_weights)`, 시드 42/43/44
- 결과 파일: `results/preds/cnn_{plain,aug}__*__s{42,43,44}.npz`, `results/logs/cnn_*_history.json`, `results/logs/colab_cnn.log`, `results/logs/colab_20261122_012229.md`(세션 기록)

## 실행 중 확인한 것
- 1GB zip을 `colab upload`로 올리면 Broken pipe로 실패했다. 그래서 Colab VM이 직접 받는 방식(`kagglehub`)으로 바꿨다.
- `/kaggle/input`은 NFS라 파일당 약 12.6ms가 걸린다(로컬 디스크는 0.6ms). 그래서 스레드 32개로 로컬 디스크에 한 번 복사한다.
- `colab exec`는 원격 셀이 실패해도 종료 코드 0을 돌려준다. 그래서 출력에서 `CalledProcessError`를 찾아 스크립트를 멈추게 했다.
- 전체 6회 학습과 예측에 약 70분이 걸렸다(01:22–02:32). 끝난 뒤 세션이 꺼진 것까지 확인했다.

Kaggle 내부 셋: plain val 0.669, test 0.601이고 aug val 0.539, test 0.545다. 그룹 분할 덕분에 내부 셋도 합성 clean과 비슷한 수준까지 내려왔다.

## 해석
1. **증강 없는 CNN은 위치와 크기 변화에 무너진다.** shift 7.2%, scale_small 4.7%로 우연 수준(1/24 = 4.2%)이다. Kaggle 사진은 구도가 거의 같아서, 손 모양이 아니라 "그 위치의 그 크기"를 외운 것으로 본다.
2. **증강은 위치·크기·어둠의 손실을 크게 메운다.** 대신 clean에서 5.6%p를 잃는다(0.632 → 0.576).
3. **어두운 조건에서는 CNN aug가 RF보다 낫다**(dark_0.5: 0.383 vs 0.193). RF는 어두우면 MediaPipe 검출부터 실패하기 때문이다(검출률 25%, EXP-003).
4. **복잡한 배경은 CNN의 약점이다.** 두 변형 모두 약 19~20%로, RF(42%)의 절반이다. 증강에 배경 변화가 들어 있지 않다.
5. 시드 간 표준편차는 대부분 3%p 이하다. aug의 scale_small만 11.8%p로 크다.

## 한계
- 소형 CNN을 처음부터 학습했다(사전학습 없음). RF는 사전학습된 MediaPipe 손 검출기 위에서 동작하므로 "같은 조건의 비교"는 아니다.
- 증강 종류(밝기·이동·확대)가 합성 변형과 겹친다. aug가 dark·shift에 강한 것은 일부는 "본 적 있는 변형"이라서다.
- 하이퍼파라미터(학습률, 해상도, 구조)는 탐색하지 않았다.
